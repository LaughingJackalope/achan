# CL-110: URL Normalization & Post Numbering Specifications

## URL Normalization Strategy

### Purpose
Ensure thread deduplication by converting variant URLs to a single canonical form.

### Normalization Pipeline

```
Input: any URL string
↓
1. Parse with java.net.URI (handles encoding)
2. Force HTTPS (http → https)
3. Lowercase scheme + host
4. Remove default ports (:443 for https, :80 for http)
5. Remove trailing slash on path (except root "/")
6. Sort query parameters alphabetically
7. Remove fragment (#section)
8. Punycode non-ASCII domains
↓
Output: canonical URL string
```

### Edge Case Handling

| Case | Behavior | Rationale |
|------|----------|-----------|
| URL shorteners (bit.ly, etc.) | Do NOT expand. Treat as-is. | Different shortlinks = different threads in MVP |
| www vs non-www | Keep as-is. `www.example.com` ≠ `example.com` | Some sites serve different content |
| Query params | Keep all, sorted alphabetically | Empty value `?foo=` vs `?foo` treated as different |
| Fragments | Always remove | Not server-relevant for content identity |
| Protocols | Always force HTTPS | Consolidate http/https variants |
| Path trailing slash | Remove (except root `/`) | `/path/` → `/path`, but `https://example.com/` stays |

### Implementation Notes
- Implement as `URLNormalizer` utility class
- Must have comprehensive test coverage for edge cases
- Normalization happens before database lookup/insert
- Store canonical URL in `Thread.url` field

## Post Numbering Strategy

### Requirements
- Sequential `post_number` within each thread
- Starts at 1 for first post in thread
- No gaps in numbering
- Concurrent post creation must not cause collisions

### Implementation Approach

**Transaction Isolation:** Use `SERIALIZABLE` isolation level

```kotlin
@Transactional(isolation = Isolation.SERIALIZABLE)
fun createPost(threadId: UUID, content: String, parentPostId: Long?): Post {
    val nextNumber = em.createQuery(
        "SELECT COALESCE(MAX(p.postNumber), 0) + 1 FROM Post p WHERE p.threadId = :threadId"
    ).setParameter("threadId", threadId).getSingleResult()

    val post = Post(
        threadId = threadId,
        parentPostId = parentPostId,
        content = content,
        postNumber = nextNumber,
        postedAt = Instant.now()
    )

    em.persist(post)
    // Also: increment thread.post_count, update thread.updated_at
    return post
}
```

### Concurrency Behavior
- Concurrent writes to **same thread**: Transactions serialize. Second waits for first to commit, then gets correct next number.
- Concurrent writes to **different threads**: Full parallelism, no blocking.

### Performance Tradeoffs
- **Cost:** Slight latency increase under high concurrency to same thread
- **Benefit:** Guaranteed sequential numbering without gaps or duplicates
- **Acceptable:** MVP target is <150ms p95 for post creation; serialization delay should be minimal
- **Future optimization:** If needed, switch to message queue for write-heavy threads (already planned for Kafka channel)

### Alternative Considered (Rejected)
Using `BIGSERIAL post_id` as `post_number`:
- ✅ Simpler, no race conditions
- ❌ Not "sequential within thread" (numbers have gaps across threads)
- ❌ Breaks spec requirement for `>>references` to be thread-scoped
